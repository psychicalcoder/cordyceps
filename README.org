#+TITLE: Cordyceps: Named Parameters for Emacs Lisp with zero runtime overhead

#+HTML: <img src="assets/watercolor_cordyceps_480.png" alt="Cordyceps" width="240" height="288">

The connascence of position (CoP) in function arguments is a serious problem that ruins the readability of Lisp code. /cl-libs/ provides ~cl-defun~ with ~&key~ allows developers to define functions called with keyword arguments, such as ~(cl-remove-if pred seq :key #'car)~. However, each time we call the function, the keyword arguments are parsed. It is usually not necessary since the keywords and the value expression are usually known at compile time. Coryceps provides similar keywords arguments but the keywords are parsed when compilation.

** Usage

Put =cordyceps.el= into =load-path=.

#+BEGIN_SRC emacs-lisp
  (eval-when-compile
    (require 'cordyceps))
#+END_SRC

** Syntax

Like normal ~defun~, except arguments can have default values. In the following example, the default values of ~reset~ and ~advance~ are ~nil~ and ~t~ respectively. To eliminate unexpected effects, using constant expressions as default values are recommanded. The default value forms are evaluated at runtime before every function call.

#+BEGIN_SRC emacs-lisp
  (let ((cnt 0))
    (np-defun counter (reset (advance t))
      "Return the counter value and advance the counter. Arguments are optional
  keyword/argument pairs.

  :reset BOOL -- if BOOL is non-nil, set the counter to zero after return.
  :advance BOOL -- BOOL is `t' by default; if BOOL is non-nil, advance the
  counter after return (or reset). `t'
  \(fn &key RESET ADVANCE)"
      (prog1 cnt
        (when reset (setq cnt 0))
        (when advance (setq cnt (1+ cnt))))))
#+END_SRC

Passing an argument must specify the keyword. Arguments can be in any order.

#+BEGIN_SRC emacs-lisp
  (counter) ;; ==> (counter :reset nil :advance t)
  (counter t) ;; ==> Error!
  (counter :reset t) ;; ==> (counter :reset t :advance t)
  (counter :advnace nil) ;; ==> (counter :reset nil :advance nil)
  (counter :advance nil :reset (should-reset-p))
  ;; ==> (let ((g487 (should-reset-p)))
  ;;       (counter :reset g487 :advance nil))
#+END_SRC

** Difference between ~cl-defun~ and ~np-defun~
*** Intuition
#+BEGIN_SRC emacs-lisp
  (cl-defun foo (&key arg1 arg2)
    (if arg1 arg2 nil))
#+END_SRC

in a overly simplified mannar, this function will be expand to:

#+BEGIN_SRC emacs-lisp
  (defun foo (&rest args)
    (let ((arg1 (cadr (plist-member ':arg1 args)))
  	(arg2 (cadr (plist-member ':arg2 args))))
      (validate-args--foo args)
      (if arg1 arg2 nil)))
#+END_SRC

Every time we call ~foo~, the arglist will be parsed before really executing the function. The form correspond to the keyword are known at compile time in most cases. So, theoretically we can define ~foo~ as with ~defun~.

#+BEGIN_SRC emacs-lisp
  (defun foo (arg1 arg2)
    (if arg1 arg2 nil))
#+END_SRC

On the call site, we can compile ~(foo :arg2 '(a b) :arg1 t)~ into: ~(foo t arg2)~.

*** Implementation
What ~np-defun~ really does is:

1. Define a internal function accepting position parameters
2. Define a wrapper function accepting named parameters. The wrapper parses the arglist and calls the internal function at runtime. ~funcall, apply, eval~ trigger the wrapper function.
3. Transforms calls to the function, into a calls to the internal function at compile time, while preserving the natural evaluation order of arglists.

Example:
#+BEGIN_SRC emacs-lisp
  (let ((arg2 '(a b))
        (arg1 t))
    (foo--internal arg1 arg2))
#+END_SRC
